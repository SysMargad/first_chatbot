# Лицензийн үүргийн өдөр тутмын хяналт → Google Chat

Obligation Register spreadsheet-ээс өдөр бүр автоматаар Google Chat space руу
удирдлагад ойлгомжтой товч мэдээ болон exception анхааруулга илгээнэ.

Эх дата: `1fS3eBYObw8l9zKv-Gz02xTWVoUZwixgk62uRDMxqI_0` — өөр эх сурвалж ашиглахгүй.

**Хуудас оноор автоматаар сонгогдоно.** Одоогийн он **ба түүнээс хойшхи**
бүх `OB <он>` хуудсыг уншина — 2026 онд `OB 2026` + `OB 2027`, 2027 онд
`OB 2027` (+ `OB 2028` үүссэн бол) гэх мэт. Өнгөрсөн оны хуудсыг уншихгүй.
`OB Master (backup)` зэрэг оны бус хуудас **хэзээ ч** ороогүй.

Нэг үүрэг хоёр хуудсанд байвал **идэвхтэй мөчлөгийг** нь сонгоно: биелчихсэн
2026 оны мөчлөгийн оронд хүлээгдэж буй 2027 оных харагдана, харин биелээгүй
хэвээр хугацаа хэтэрсэн зөрчил нуугдахгүй.

Одоогийн болон ирээдүйн оны хуудас огт байхгүй бол хамгийн сүүлийн оныг түр
ашиглаад Chat карт дээр **⚠️ анхааруулга** харуулна — чимээгүй хоосон тайлан
гарахаас сэргийлнэ.

## Юу илгээгддэг вэ

### 1. Өдөр тутмын тайлан (`daily`)

Гүйцэтгэх удирдлагын тайлангийн бүтэцтэй, таван хэсэгтэй нэг карт.
Толгойд огноо, идэвхтэй үүргийн тоо, уншсан хуудас, ажилласан цаг
(`Snapshot HH:MM`). Толгойн өнгө: 🔴 хугацаа хэтэрсэн эсхүл блоклогдсон
лиценз байна / 🟠 долоо хоногт дуусах үүрэг байна / 🟢 хэвийн.

**01 · ЛИЦЕНЗИЙН ПОРТФЕЛИЙН ТОЙМ** — зургаан KPI, дор нь нэг догол мөрийн
удирдлагын товч үнэлгээ.

| KPI | Юуг тоолох |
|---|---|
| Нийт лиценз | Бүх лиценз (олгогдсон + сонгон шалгаруулалтаар дугаар хүлээгдэж буй) |
| Ноцтой лиценз | Хугацаа хэтэрсэн эсхүл блоклогдсон үүрэгтэй лиценз |
| Идэвхтэй үүрэг | `Not applicable`-ийг хассан үүрэг |
| Хугацаа хэтэрсэн | Due date өнгөрсөн идэвхтэй үүрэг |
| 30 хоногт дуусах | Ойрын 30 хоногт дуусах (дотор нь 7 хоногийнх тусад нь) |
| Evidence gap | Нотлох баримт `Missing` эсхүл `Partial` |

**02 · ЛИЦЕНЗ ТУС БҮРИЙН ТӨЛӨВ** *(эвхэгддэг)* — компаниар бүлэглэсэн
лицензийн жагсаалт. Мөр бүр: төлөвийн өнгө (🔴 хэтэрсэн/блоклогдсон ·
🟠 анхаарах · 🟢 хэвийн), лицензийн дугаар, төслийн нэр, идэвхтэй/нийт
үүрэг, хэтэрсэн, 30 хоногт, нотолгоо дутуу, ойрын due date. Доор нь
**компанийн нэгдсэн scope** (олон лицензэд нэгэн зэрэг хамаарах үүрэг —
лицензийн тоонд давхардуулж оруулаагүй).

**03 · TIER АНГИЛЛЫН ХУРААНГУЙ** — Tier 1/2/3 тус бүрээр exception /
идэвхтэй харьцаа, хэтэрсэн · RED · нотолгоо дутуугийн задаргаа.

**04 · УДИРДЛАГЫН АНХААРАХ АСУУДАЛ** — хугацаа хэтэрсэн болон блоклогдсон
үүргүүд. **Ижил үүргийг лицензээр нь нэгтгэдэг:** OB-05 нь 7 лиценз дээр
адилхан хэтэрсэн бол 7 давхардсан блок биш, нэг блок дотор нөлөөлсөн
лицензүүд компаниар жагсана.

```
🔴 194 хоног хэтэрсэн · OB-05 · 7 лиценз
Хайгуулын ажлын жилийн тайлан хүргүүлэх (02/15)
NGE: XV-020915 · TIM: XV-022954 · NCM: XV-022905, XV-021395, XV-023101 · …

⚠️ LICENSE / SUSPENSION RISK
Хугацаа хэтэрсэн тул тусгай зөвшөөрлийн үйл ажиллагаанд хязгаарлалт
үүсэх эрсдэлтэй.

Owner · Ахлах геологич
```

**05 · ҮҮРГИЙН ТӨРЛИЙН EXCEPTION** *(эвхэгддэг)* — OB-05, OB-07 гэх мэт
төрөл бүрээр бүх лицензээр нэгтгэсэн үзүүлэлт.

Жагсаалтууд `MAX_EXCEPTION_ITEMS` (анхдагч 10) ба `MAX_LIST_ITEMS`
(анхдагч 5)-аар хязгаарлагдана; илүү гарвал "Нэмэлт N …" гэж тэмдэглэнэ.

> **Эрсдэлийн тайлбарын тухай.** `LICENSE / SUSPENSION RISK` гэх мэт шошго
> болон доорх өгүүлбэрийг [`risk.py`](obligation_monitor/risk.py) **загвараар**
> үүсгэдэг — Tier болон төлөвөөс хамаарч ерөнхийлж бичсэн, эрх зүйн албан
> ёсны дүгнэлт БИШ. Хууль/комплаенсийн багаар хянуулж, шаардлагатай бол
> зөвхөн тэр файлын текстийг засна.

> **Chat-ийн хязгаарлалт.** Google Chat карт HTML тайлан шиг хүснэгт,
> өнгөт хайрцаг, badge зурж чаддаггүй. Дээрх бүтэц нь cardsV2-ийн
> боломжид (section, columns, decoratedText, эвхэгддэг хэсэг) тааруулсан
> хамгийн ойрын хувилбар. Одоогийн карт ≈ 11.5 KB — Chat-ийн 32 KB
> хязгаарын дотор.

### 2. Exception анхааруулга (`exceptions`)

Зөвхөн **шинээр илэрсэн** тохиолдлыг илгээнэ — нэг асуудал давтагдахгүй.
Мөр бүрээс хамгийн ноцтой нэг шалтгааныг л сонгоно.

| Түвшин | Нөхцөл |
|---|---|
| 🔴 КРИТИК | Хугацаа хэтэрсэн |
| 🔴 КРИТИК | Төлөв: Overdue / Rejected / Exception open |
| 🔴 КРИТИК | Tier 1 үүрэг 7 хоногийн дотор дуусах |
| 🟠 АНХААР | 30 хоногт дуусах ба нотлох баримт Missing/Partial |
| 🟠 АНХААР | 7 хоногт дуусах ба ажил эхлээгүй |
| 🟡 БАРИМТ | 30 хоногт дуусах ба Drive холбоосгүй |

### 3. Тайлангийн хяналт (`watchdog`)

### 2. Google хандалт тохируулах

Скрипт хүн биш, **service account**-аар spreadsheet уншина. Ингэснээр
хэн нэгний нэвтрэлтээс хамаарахгүй, серверт ч ажиллана.

1. [console.cloud.google.com](https://console.cloud.google.com) → project сонгох (эсхүл шинээр үүсгэх)
2. **APIs & Services → Library** → `Google Sheets API` → **Enable**
3. **APIs & Services → Credentials → Create credentials → Service account**
   - Нэр: `obligation-monitor` · Role шаардлагагүй → **Done**
4. Үүссэн service account дээр дарж → **Keys → Add key → Create new key → JSON**
   - Татагдсан файлыг `service-account.json` нэрээр төслийн үндэс хавтсанд хийнэ
5. JSON доторх `client_email` утгыг хуулна
   (ж: `obligation-monitor@төсөл.iam.gserviceaccount.com`)
6. **Spreadsheet-ээ нээж → Share → тэр имэйлийг Viewer эрхээр нэмнэ**

> 6-р алхмыг мартвал `403 The caller does not have permission` гарна.

### 3. `.env` бэлдэх

`.env` файлд Google Chat webhook URL байх ёстой. Одоо байгаа файл
нүцгэн URL агуулж байгаа бөгөөд **тэр хэвээрээ ажиллана**. Тодорхой болгох
бол `.env.example`-ийг үлгэр болгож дараах хэлбэрт оруулж болно:

```
CHAT_WEBHOOK_URL=https://chat.googleapis.com/v1/spaces/.../messages?key=...&token=...
SPREADSHEET_ID=1fS3eBYObw8l9zKv-Gz02xTWVoUZwixgk62uRDMxqI_0
GOOGLE_APPLICATION_CREDENTIALS=service-account.json
```

### 5. Хуваарь суулгах (Windows Task Scheduler)

```powershell
# Өдөр бүр 10:00 — ерөнхий товч
schtasks /create /f /tn "Obligation daily" /tr "C:\Users\margad.p\Desktop\FIRST_CHATBOT\run.bat daily" /sc daily /st 10:00

# 10:00, 14:00, 18:00 — exception хяналт (ажлын цагт л)
schtasks /create /f /tn "Obligation exceptions" /tr "C:\Users\margad.p\Desktop\FIRST_CHATBOT\run.bat exceptions" /sc daily /st 10:00 /ri 240 /du 09:00

# Даваа 10:30 — тайлангийн хяналт
schtasks /create /f /tn "Obligation watchdog" /tr "C:\Users\margad.p\Desktop\FIRST_CHATBOT\run.bat watchdog" /sc weekly /d MON /st 10:30
```

`/ri 240 /du 09:00` = 10:00-аас эхлэн 9 цагийн турш 240 минут тутам давтана,
өөрөөр хэлбэл 10:00 · 14:00 · 18:00. Шөнө мэдэгдэл ирэхгүй.

`run.bat` нь гаралтыг `run.log`-д бичнэ.

> **Анхаар:** Task Scheduler зөвхөн компьютер асаалттай үед ажиллана.
> Амралтын өдөр эсхүл унтраалттай үед мэдэгдэл алгасна. Тасралтгүй
> ажиллуулах бол cloud VM, GitHub Actions (cron) эсхүл Cloud Run Job руу
> зөөнө — код өөрчлөх шаардлагагүй, зөвхөн `.env` + `service-account.json`
> хоёрыг secret болгож өгнө.

## Техникийн тэмдэглэл

- **Багануудыг гарчгийн нэрээр олдог** (`Obligation ID`, `Дараагийн due date`, …).
  Register 57 баганатай, дунд нь хоосон болон helper багана олон тул индексээр
  хандвал эмзэг. Гарчиг өөрчлөгдвөл [`sheets.py`](obligation_monitor/sheets.py)
  доторх `_COLUMNS` толийд шинэ нэрийг нэмнэ.
- **Хуудас бүрийг өөрийнх нь оноор уншина.** `OB 2027` дээр `2027 Одоогийн
  статус`, `OB 2026` дээр `2026 Одоогийн статус` баганыг хайж, олдохгүй бол
  `Active … (helper)` багана руу шилжинэ.
- Нэг ID давтагдвал **идэвхтэй мөчлөгийг** сонгоно: идэвхтэй → due date-тай →
  шийдэгдээгүй зөрчил → дуусаагүй; тэнцвэл due date нь ойр байгааг нь.
- **Биелсэн (`Completed` / `Closed`) үүргийг хугацаа хэтэрсэн гэж тоолохгүй.**
  Жишээ нь 02/15-нд тайлан хүргүүлээд дуусгасан бол due date өнгөрсөн байх нь
  хэвийн — зөрчил биш.
- `Not applicable` эсхүл хоосон статустай мөрийг тооцоололд оруулахгүй.
- Огноог `Date`, `yyyy-mm-dd` текст болон Sheets-ийн серийн дугаар
  (ж: `46324`) гурван хэлбэрээр таньдаг. `m/d/yyyy` хэлбэрийг АНУ-ын
  дарааллаар (сар/өдөр) уншина — run log дээрх `8/6/2026` ийм байсан.
- Evidence нь `Not yet due` / `Not applicable` бол Drive холбоос
  шаардахгүй — тийм мөрийг "холбоосгүй" гэж тоолохгүй.
- Өчигдрийн тоо болон мэдэгдсэн exception `state.json`-д хадгалагдана.
  Эхнээс нь эхлүүлэх бол тэр файлыг устгана.
